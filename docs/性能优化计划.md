# 性能优化计划（教学版）

逐项优化 FastReplace 前端性能，每项都教你怎么改、怎么用浏览器 DevTools 验证效果。

---

## 1. scrollToBottom 节流（chatWidget.vue）

**问题**: 流式响应每个 token 都调 `scrollToBottom()`，每秒可能触发 30-50 次 DOM 重排。

**怎么改**: 用 `requestAnimationFrame` 节流，每帧（16ms）最多滚动一次。

**怎么验证**:
1. F12 → Performance 面板 → 点 Record
2. 发一条消息等 AI 回复
3. 停止录制，看 Timeline 里的紫色区域（Layout/重排）
4. 优化前：密密麻麻的紫色块；优化后：均匀分布，间隔约 16ms

---

## 2. Markdown 渲染缓存（chatWidget.vue）

**问题**: `v-html="renderMarkdown(msg.content)"` 每次响应式更新都对所有消息重新调 `md.render()`。

**怎么改**: 流式中的消息正常渲染；已完成的消息缓存 HTML，不重复计算。

**怎么验证**:
1. F12 → Console，在 `renderMarkdown` 里加 `console.count('render')`
2. 发消息后观察：优化前每次更新调用次数 = 消息总数 × N；优化后只有当前流式消息在调用

---

## 3. v-for key 优化（chatWidget.vue）

**问题**: `:key="index"` 用数组索引，新消息插入时 Vue 会重新渲染之前所有消息的 DOM。

**怎么改**: 用 `msg.timestamp` 作为唯一 key。

**怎么验证**:
1. F12 → Elements 面板，找到消息列表的 DOM
2. 发新消息，观察之前消息的 DOM 节点是否被替换（闪紫色 = 重新渲染）
3. 优化后：只有新消息的 DOM 会闪

---

## 4. chatWithAI 超时+取消（api/ai.js）

**问题**: `chatWithAI` 无 AbortController，网络异常时 Promise 永不 resolve。

**怎么改**: 加 AbortController + 3 分钟超时。

**怎么验证**:
1. F12 → Network 面板，找到 `/api/ai/chat` 请求
2. 断网或后端停掉，3 分钟后应自动报"超时"错误
3. 优化前：一直 pending；优化后：超时自动结束

---

## 5. Vite 构建分包（vite.config.js）

**问题**: `npm run build` 打出的 JS 全在一个大文件里。

**怎么改**: 用 `manualChunks` 把 element-plus、markdown-it 拆成独立 chunk。

**怎么验证**:
1. 优化前先跑 `npm run build`，记下 dist/assets 里最大的 .js 文件大小
2. 优化后再跑 `npm run build`，对比：单文件应该变小，出现多个 chunk 文件
3. F12 → Network → 刷新页面，看 JS 请求数和大小

---

## 6. localStorage 持久化瘦身（stores/chat.js）

**问题**: actions 里的 result（工具调用返回的 JSON）被持久化到 localStorage，浪费空间。

**怎么改**: persist 配置里过滤掉 `actions[].result`。

**怎么验证**:
1. F12 → Application → Local Storage → 找 `chat` 的 key
2. 优化前：包含大量 `result: {...}` 数据；优化后：actions 里 result 为 null
